# Bounded physical-recovery staging

Inactive component for the approved t3.medium Standard / 160 GiB gp3 / max48h conversion window. It requires a reviewed Amazon AL2023 x86_64 AMI and the existing reconciled Dev VPC/subnet. It creates a separate security group with no ingress and only HTTPS egress, an IMDSv2-only host, and one temporary public IPv4 included in the approved estimate. No SSH key or EIP is created. Amazon-provided VPC DNS is used.

The only allowed instance profile is the temporary `chico-dev-restore` profile from restore-access. The caller must depend on the completed access module, use the same fixed lease, validate ownership/quota/funding/current dates and review the full saved plan before activation. Source compatibility and file/WAL integrity remain separate gates before physical recovery. Bootstrap installs OS tools and prepares empty protected directories; it starts no database or transfer and carries no cipher/password/token.

The absolute persistent systemd timer stops compute at the reviewed expiry and survives reboot. IAM independently denies source/destination S3 outside its lease. Neither mechanism terminates the instance or deletes data at expiry. Stopped disks still cost money. Root deletion occurs only as part of an explicitly reviewed cleanup termination after restored Dev data, its own backup and independent recovery are proven; its recorded volume ID must be included in that cleanup review.

Host, volume and security-group tags use `env=restore`, outside the permanent CI apply role's `project=chicoai/env=dev` write scope. A Dev CI actor must not be able to retag or modify the sensitive recovery host. Temporary spend is included in the account-wide gross budget and approved project envelope; account/temporary cost reconciliation is required, and this must not be represented as already covered by the existing env=dev budget filter. No extra budget, cost-tag activation or shared policy change is performed here.

The full staging root, source-version manifest, private cipher transfer, toolchain/image build and runtime preflight are still required. Mock tests and shell syntax checks prove configuration invariants, not actual stop timing, egress behavior, SSM access, integrity or database recovery. Live Core verification must prove empty ingress, reviewed tags/profile, current lease, timer, encrypted capacity and no concurrent ARM builder before any source transfer.
